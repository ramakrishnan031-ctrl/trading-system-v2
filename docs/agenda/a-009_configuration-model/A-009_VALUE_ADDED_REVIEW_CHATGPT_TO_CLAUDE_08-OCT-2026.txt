7. REQUIRED CORRECTION #5 — BROKER API "AUTHORITY" LANGUAGE
======================================================================

The V2 inputs correctly point toward broker APIs for margins and charges.

But keep the distinction:

    /margins/orders
        = broker-side order margin CALCULATION API

    /charges/orders
        = broker-side order charge CALCULATION API

Neither should automatically be described as the complete "broker account
truth" for all runtime state.

The broker remains authoritative for actual live broker state; these APIs
provide broker calculations for the specific requested order(s).

This is especially important because /margins/orders considers existing
positions/open orders when calculating order margin.

Recommended V2 wording:

    "Use broker APIs for broker-calculated order margin/charge references
     where available; use broker state endpoints for actual live account
     state."

Keep this PROPOSED. Do not turn it into a V2 decision in A-009.
