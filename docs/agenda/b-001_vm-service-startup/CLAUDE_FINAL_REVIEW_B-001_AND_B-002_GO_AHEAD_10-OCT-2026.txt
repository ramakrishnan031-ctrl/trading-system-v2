2. REQUIRED DOCUMENTATION IMPROVEMENT — EVIDENCE PRIORITY

B-001_manual.md section 2 currently states a general source priority:
“production source and configuration > production records > testing captures > supplied records > user recollection > interpretation”.

That hierarchy is too broad if read literally. Evidence priority depends on the claim being tested:
- For “what does the repository code/config define at commit 970aabf?”, the production source is primary.
- For “what was installed/enabled/running on a particular date?”, a contemporaneous dated host record is usually stronger than a repository declaration.
- For “what was installed on the testing VM?”, its machine capture is primary for that testing VM only.
- For “what did Rama personally observe?”, his recollection is the primary evidence of his recollection, but may still conflict with independently dated machine records about system state.
- For the final production VM state after its deletion, none of these sources may establish the answer; it must remain UNKNOWN / NOT ESTABLISHED.

Suggested replacement wording:
“Evidence is claim-specific, not governed by one universal ranking. Repository source establishes what the named baseline defines; dated host records establish only the states/events they record; testing captures establish testing-VM state only; supplied records and user recollection retain their own provenance and limitations. When evidence conflicts, state the conflict and assess source fitness for the specific claim. Do not use a repository declaration alone to infer historical installation or final host state.”

This is a clarity improvement, not a change to B-001's findings. If B-001 is already frozen under DR-035, record it as a minor editorial follow-up or amend only through the established erratum/reopen process; do not silently alter the frozen copy.
