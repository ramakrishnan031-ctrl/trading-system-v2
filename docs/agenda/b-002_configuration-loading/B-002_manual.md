## 4. The configuration directory, fixed-path readers and the environment (FACT, SOURCE-VERIFIED unless marked)
- `config_dir = Path(args.config) if args.config else Path("config")` (main.py line 2099); a relative path is resolved against the working directory. The repository unit sets WorkingDirectory to the deployed tree and passes no --config (A-009 section 4). Whether --config was ever used is NOT ESTABLISHED (RAMA (EXPECTED), B2-10: "OPEN QUESTION"; HISTORICAL (Rama), A-009 Q4: UNKNOWN).
- Readers that do not follow --config: the webhook receiver and the paper quote provider read `config/symbol_aliases.yaml`, effect telemetry reads `config/expected_managers.yaml`, the token and the state database come from fixed `data_store/` paths, and the holiday sentinel from `logs/`, each relative to the working directory. Start-up check 12 reads requirements.txt from the configuration directory's parent. INTERPRETATION: a start with --config pointing elsewhere would have combined that directory's AppConfig, accounts, instruments and strategies with the working directory's aliases and manager registry.
- Configuration objects: main.py holds the AppConfig returned by load_all and passes sub-configurations to constructors (for example the rate limiter, product resolver, cost calculator, market windows, kill switch and notifier, lines 2243 to 2350 and 2617 to 2642); the modules then read those values as attributes. RECORD-DERIVED (24-Jul investigation, "measured"): "load_all ... is a module-level function, no singleton"; "main.py calls it once at Phase 0b, holds the AppConfig, and passes sub-configs as constructor parameters to each subsystem via DI"; "config is immutable for the process lifetime". The exceptions are the fixed-path readers above, which read their files themselves.
- The environment reached the service process by two routes (FACT, SOURCE-VERIFIED for the code; CURRENT EXTERNAL FACT for the package's rules). First, the repository unit specifies EnvironmentFile=.env, which systemd reads before it starts main.py (A-010 section 5). Second, main.py imports scripts.zerodha_login (line 106), whose module-level load_dotenv() (line 36) therefore runs inside the service process as it starts. By python-dotenv 1.2.2's rules (section 2) that call searches upward from scripts/ and so finds the tree's .env, and with override=False it keeps every variable already set and adds any variable not yet set, for example one on a line that systemd's parser skipped. This corrects A-010 section 5, which said "main.py has no load_dotenv" and that zerodha_login.py loads from the "current folder" (erratum E-2, section 15).
- INTERPRETATION / AUDIT LEAD: where the two parsers read a line differently, the service process could have held a variable that systemd did not set; whether that ever happened in a run is NOT ESTABLISHED, because nothing measured it (V2_DESIGN_LOG Q-40 (k)). INTERPRETATION: a manual run of main.py outside systemd (as CONFIG_GUIDE.md describes for paper runs) still received .env through this import.
- Time sources for configuration: the holiday guard and the loader's holiday file name use the host's local date (`date.today()`); start-up check 1 computes the year in IST explicitly; check 11 uses the time authority's IST date. On the IST host they agreed (B-001 section 11).
