However, §4.2 currently groups “no database or no schema_meta table” into a row described as “a fresh build”, while the next row describes the defect for an existing database with a missing version row, a non-integer value, or an OperationalError. An EXISTING database whose `schema_meta` table itself is missing appears to fall into the same unsafe `None` path, but the defect row does not explicitly name that case. The wording could therefore be read as treating “schema_meta table absent” as safe only for a fresh database.

Required change:
State explicitly that `None` is safe only when the database is genuinely new/empty under the source's actual fresh-build path. If a database already contains legacy/application tables but has no `schema_meta` table, that is part of the same conditional latent defect: the code treats it as a fresh database, skips version checks and migration gating, and proceeds to run `schema.sql`. Keep the historical result as NOT ESTABLISHED / NO OBSERVED OCCURRENCE FOUND.

Suggested replacement for the first two rows of §4.2 (adapt the wording to the existing table format):

- No database exists at the target path and the open creates a genuinely fresh database: the fresh-build path runs schema.sql and stamps version 45. This is the intended fresh-build case evidenced by the source/test.
- `None` is returned for an existing database because `schema_meta` is absent, the version row is absent, the value is not an integer, or the version read raises an `OperationalError`: the code treats the database as new, bypasses the newer-version check and migration gate, and runs schema.sql without the required rebuilds. KNOWN DEFECT — CONDITIONAL CODE PATH / LATENT; NO OBSERVED OCCURRENCE FOUND. Depending on the existing schema and statements encountered, the script may fail part-way or may stamp 45 over tables that were not rebuilt.

Do not assert that every such database will be stamped successfully; retain the manual's conditional branches. Make D12 and §17 item 1 use the same complete list of conditions.
