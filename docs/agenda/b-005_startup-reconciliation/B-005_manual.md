## 6. What a returned startup pass proved, and the outcome of each condition at a start (authoritative for B-005)

### 6.1 The return value and the boot flag (FACT, SOURCE-VERIFIED)
- main.py reads only the length of PASS 1's list, to log it (S9). The boot flag is set on the next line whatever the list holds (S8), and nothing in the start reads the list again.
- An empty list means one of: nothing to report (no local open trade, no broker position and nothing found by CHECK6, CHECK9, G5b or the capital checks); a positions read that failed with E1 or E2 and nothing else found; or an aborted cycle (E3, E4). A non-empty list means the cycle reached its end, not that every check ran (E1, E2).
- The lock's empty list (E6) cannot occur at the startup passes.
- So the boot flag records that PASS 1 was called and returned. KNOWN DEFECT — CONDITIONAL CODE PATH / LATENT; NO OBSERVED OCCURRENCE FOUND at a start: after an aborted PASS 1 the flag is set and the start continues, so the phantom capital that the boot invariant exists to release before any trade (S7's comment) is not released by that pass. PASS 2 runs the same cycle before the signal processor starts and releases it if it succeeds; if PASS 2 aborts too, nothing tests the outcome, and the first successful poll releases it, 15 s or more after the signal processor and the webhook started. The abort path itself is recorded in a session (05-Aug, section 4.2).
- What did end the start: an active kill at the kill check (S11). The kills that PASS 1 can set are CHECK9's SOFT_KILL (SR12) and the drift handler's SOFT_KILL or HARD_KILL from CHECK7 (SR13); a SOFT_KILL left by a failed EOD recovery fire (S6) is met by the same check (SR20).
