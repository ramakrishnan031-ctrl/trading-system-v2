2. POWERSHELL DEFECT — ACCEPTED
- Correct: `git commit -m $msg; git push` runs the push even when the commit fails. A semicolon only separates statements, and a native command's non-zero exit code does not stop Windows PowerShell. Both affected runs (B-004 to 31d85d2, B-005 to de63c4e) committed successfully and their remotes match their packages, so no harm resulted; the defect is in the template.
- Corrected PART 2 for every future package (one script block, so a failed step ends the whole block even when pasted):

  & {
    if (-not $expected -or $fail -ne 0) { "PART 1 did not pass in this window: nothing committed."; return }
    git commit -m $msg
    if ($LASTEXITCODE -ne 0) { "COMMIT FAILED: nothing pushed. Send the output to Claude."; return }
    $parent = (git rev-parse "HEAD~1").Trim()
    $files  = @(git diff-tree --no-commit-id --name-only -r HEAD)
    $d3 = Compare-Object -ReferenceObject ($expected | Sort-Object) -DifferenceObject ($files | Sort-Object)
    if ($parent -ne $base -or $d3) { "COMMIT CHECK FAILED (parent or file list): not pushed. Send the output to Claude."; return }
    git push
    if ($LASTEXITCODE -ne 0) { "PUSH FAILED. Send the output to Claude."; return }
    $local  = (git rev-parse HEAD).Trim()
    $remote = ((git ls-remote origin refs/heads/main) -split "\s+")[0]
    if ($local -eq $remote) { "PUSHED AND VERIFIED: remote main = $remote" } else { "REMOTE DIFFERS: local $local, remote $remote. Send the output to Claude." }
  }

  PART 1 gains, before staging: `git fetch origin`, then a check that HEAD and origin/main both equal $base (the expected parent, for E-5 de63c4e9087976940feec94dd024213c95643dd1).
