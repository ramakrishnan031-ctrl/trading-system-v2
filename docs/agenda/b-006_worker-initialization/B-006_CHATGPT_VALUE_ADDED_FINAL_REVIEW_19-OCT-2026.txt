2. TECHNICAL FINDINGS THAT SHOULD BE PRESERVED

2.1 The nine early starts are the central finding
The sequence is stated consistently in the manual: four threads start during construction on every start, and five optional/shadow-related threads start in Phase 0e under the repository configuration, giving nine before PASS 1. The later Phase 0g workers start after reconciliation. TH3, the MIS auto square-off poller, is among the early starts and has an exit-placement capability. This is a code-path capability, not proof that an exit occurred before PASS 1 on a historical start. Keep the occurrence UNKNOWN / NOT ESTABLISHED.

2.2 Inventory counts are correctly qualified
“31 inventory rows” is not “31 simultaneously running threads”. The manual distinguishes the 31 inventory rows, the 25 named threads calculated for a live start with repository configuration, waitress task threads, and pools whose workers are created as work arrives. Keep that distinction in the final statement, summaries and future references.

2.3 Initialization is not readiness
The inspected start path does not wait for workers to report running, connected, subscribed, receiving ticks or ready. The feed's connect call is not a subscription or first-tick barrier. The manual appropriately leaves global readiness to B-007. Do not let the “System Active” message be read as proof that all workers or the market-data path were healthy.

2.4 Late exit and process lifetime are scoped correctly
The manual distinguishes code-path interpretation, CPython/library source, a scratch-library test, and historical occurrence. The claim that a late exit can wait for executor work and a non-daemon HARD_KILL flatten worker is not a measured production duration. Occurrence remains NOT ESTABLISHED. Keep this qualification in X4 and the final statement.

2.5 Feed wiring and alert claims are scoped
The wording “no caller in the runtime files searched” is better than a universal “no caller exists”. The inert configuration and unwired notifier are findings within the stated search scope. Preserve the search scope beside the conclusion.

2.6 Historical failures are not generalized
The TGT retry incident on 22–23 June is record-derived and specific. It does not establish that all worker errors were silent. The order monitor's three-failure self-stop is a separate source finding. Keep these as separate rows.

2.7 Paper/live and source provenance
The manual does not claim full paper/live parity. It states paper mode does not open the WebSocket and records the relevant mode-specific differences. It also separates the production baseline from the testing tree, dated records, library source, and repository configuration from installed-host state. These distinctions are essential and should not be compressed away in summaries.
