A. Pinned configuration is not installed runtime evidence.
The pinned configuration declares require_hmac: false, but the installed value on either terminated VM is not established. The records may support an inference, but the manual must not convert that inference into a fact. Preserve the distinction between source/config declaration, record-derived claims, and unknown historical runtime state.

B. Secret presence is not secret strength.
The code path requires WEBHOOK_SECRET to be set and non-empty before constructing the receiver, but the inspected code does not establish a length/strength policy. The receiver’s test-only no-secret path and the main.py startup guard must be documented separately; do not imply every possible receiver construction path is protected by the startup guard.

C. The two routes are not equivalent.
POST /webhook authenticates the raw request body; GET /health passes an empty byte string to the same authentication helper. The resulting constant/replayable health signature and the empty-body POST consequence are correctly classified as source-derived interpretation rather than observed production traffic. Preserve that label.

D. Test inspection is not test execution.
The package says tests were inspected, not run. Do not paraphrase test assertions as proof of installed production behaviour.

E. Historical rotation evidence remains conflicted.
The records disagree about dates/location/count of rotations. Preserve the conflict and U-03 as open. Do not infer that a retired secret was actively rejected just because a passive check recorded zero 401s.

F. Exposure and transport claims must remain bounded.
The legacy token remains treated as exposed under the established governance record. The source repository does not establish what every installed proxy, network device, or historical log recorded. Do not widen the findings beyond the evidence and the defined search scopes.

G. Preserve the process deviation openly.
