4. THE MANUAL: TITLE, PURPOSE, SCOPE AND EXCLUSIONS
==============================================================================
File: C-004_manual.md (Markdown, ASCII only). Title: "C-004 - LEGACY FIELD AND SYMBOL VALIDATION". Status line: "DRAFT
(revision 0)" until a freeze is approved.
Purpose: a detailed, evidence-backed technical booklet on legacy field and symbol validation as it existed at the pinned baseline.
For every check it documents the chain INPUT -> SOURCE -> LOGIC -> GUARD / ORDER -> OUTPUT OR FAILURE -> STORAGE / HAND-OFF ->
NEXT CONSUMER, with file, function, configuration key and line evidence wherever the research supports it.
Boundary: the legacy system is DEAD / REFERENCE ONLY. Documentation only: no repair, tuning, implementation, operational revival or
V2 design. V2 material (Rama's V2-1 input) stays out of the manual (W-1; open point 1).
In scope: request-level checks against per-symbol checks, in their actual order; payload fields, types, shapes, transformations and
failures; symbol stripping, alias lookup, exclusions, the empty-symbol check, the price check, the expiry boundary, and what is not
checked; the symbol's identity at each boundary; the instrument master's absence from intake, its build context, exact-case
lookups and documented fallbacks; outcomes and side effects (HTTP and per-symbol results, rows, queue, logs, audit counts, the
next consumer); the first later stop for an unknown symbol at the quote fetch; MIS eligibility as a limited cross-reference;
production/testing and paper/live only as far as the pinned source, frozen manuals and the 17-Sep testing capture support.
Exclusions: the gates and authentication (C-003, frozen; position only); deduplication and claims (C-005); queue, persistence,
processing and expiry rules (C-006 to C-009); scanner-to-strategy mapping (C-010); the EOD route (C-011); the instrument build
(A-004); secondary screening and MIS handling (D-003, G-007); order construction (G-002); tick and lot size (E-012, F-005).
