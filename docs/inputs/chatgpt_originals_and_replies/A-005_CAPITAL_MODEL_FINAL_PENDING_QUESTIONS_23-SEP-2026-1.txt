    ONE REAL-CASH CAPITAL BASIS
             |

             |

                         |

             broker-specific margin requirement
                         |

                    quantity

The key mathematical rule is:

    required_margin_pct
        = broker-required cash / order notional

    maximum_notional
        = cash_budget / required_margin_pct

NOT:

    cash_budget × required_margin_pct

Example values are intentionally NOT frozen here.

PART 3 — BROKER MARGIN FINDING
============================================================

The Zerodha Equity Margin Calculator provides scrip-specific MIS/CO margin information.

More importantly, Zerodha's Kite Connect margin-calculation API can calculate margin for a specific proposed order.

However, an important broker-side limitation must be preserved:

The margin-calculation API does NOT by itself guarantee that a particular equity is eligible for MIS. Zerodha's own developer discussion explains that scrip-level RMS blocks are separate and that the client must check the MIS-eligible list before relying on margin calculation.

Therefore:

    MIS eligibility check
            +
    order-specific margin calculation

are separate controls.

This directly answers the earlier question about using the order window / broker calculation for a stock not present in the normal margin-eligible list:

    The order-margin calculation can be used as a broker-side
    margin calculation/validation mechanism, BUT it must not
    be used alone to infer MIS eligibility.

Sources:
- Zerodha Equity Margin Calculator:
  https://zerodha.com/margin-calculator/Equity/
- Kite Connect margin API:
  https://kite.trade/docs/connect/v3/margins/
- Zerodha developer discussion on MIS eligibility vs margin API:
  https://kite.trade/forum/discussion/8400/kite-connect-api-update
