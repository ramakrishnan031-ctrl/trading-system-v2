17. IMPORTANT CROSS-TOPIC POINTS — PLEASE DO NOT LOSE
======================================================================

These are not all A-006 decisions, but they should remain visible for later
agendas where relevant:

1. All user/business/system decision values should be configuration-driven;
   do not hardcode them in Python.

2. Broker is the source of truth for live broker state.

3. Daily capital basis is locked; reconciliation must not silently rebase it.

4. Margin data should be dated/auditable.

5. Margin refresh success and failure should generate appropriate alerts.

6. No silent repeated broker/API failures.

7. Broker eligibility and broker margin calculation are separate concepts.

8. Actual filled quantity/price must be distinguished from intended order values.

9. Product semantics must be explicit (MIS/CNC/etc.).

10. Legacy paper-mode code is historical evidence only; NEW SYSTEM is live-only.

11. Do not assume legacy CO/BO/BRACKET configuration means actual historical use.

12. Do not assume Testing/Sandbox is identical to Production without evidence.

13. Any broker-specific rule should be confirmed against current broker
    documentation/API behaviour before implementation.
