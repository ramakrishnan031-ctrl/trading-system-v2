NEW-SYSTEM INPUTS ALREADY RECORDED — DO NOT REANSWER UNLESS CHANGED
======================================================================

The following were already supplied during the earlier Broker Model review
and are retained here only so they are not lost:

1. NEW SYSTEM broker preference:
       Zerodha only.
   Angel One should not be carried forward merely because it exists in legacy.

2. Broker authority preference:
       Broker should be authoritative for live broker facts such as funds,
       orders, fills, positions, average price, P&L, margin/eligibility and
       broker IDs, subject to a final field-by-field authority matrix.

3. Authentication preference:
       Headless/no-manual workflow is preferred if technically possible
       under current Zerodha requirements.

4. Authentication failure preference:
       Reject new entries; continue protection/reconciliation of existing
       positions where broker access permits; alert Telegram + Email.

5. Alert convention:
       Where an alert is required, Telegram + Email.

6. Intraday:
       Retain intraday trading; exact current Zerodha-supported execution/
       protection mechanism must be verified before implementation.

7. Delivery:
       Retain Delivery/GTT; prefer broker-managed future-day TGT/SL where
       supported rather than unnecessary long-running application-side
       Delivery exit logic.

8. Margin:
       Do not use invented universal leverage.
       Use broker/product/stock-specific current margin/eligibility evidence.

9. Order-time margin:
       Morning/reference margin is not silently rebased during the day.
       Order-time broker margin/API is the final live validation input.

10. No margin data:
       Previously recorded preference was to treat the requirement as
       100% cash requirement and alert, subject to final implementation
       discussion.

11. Broker evidence:
       Preserve broker order ID, exchange order ID where available,
       submission/acknowledgement, status/fill history, margin response,
       broker position/funds snapshots, rejection/error evidence and
       reconciliation timestamps.

12. Partial fill:
       Manage filled quantity; cancel/release unfilled remainder when the
       relevant exit/protection condition requires it; alert the partial-fill
       state.

13. Timeout:
       Reconcile before treating a broker timeout as a failed order, because
       the broker may have accepted the order.

14. Retry:
       Any retry must avoid duplicate broker orders and retain explicit
       attempt identity/linkage.

15. Live-only:
       NEW SYSTEM is intended to be LIVE ONLY; paper mode is not required as
       a production operating mode.

These are NEW-SYSTEM inputs, NOT legacy facts and NOT frozen implementation
decisions unless separately approved.
