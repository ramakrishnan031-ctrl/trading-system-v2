============================================================
IMPORTANT REPOSITORY FINDINGS ALREADY ESTABLISHED
============================================================

1. core/config_loader.py is the authoritative loader for the eight non-strategy
Appconfig YAML files; it hashes raw bytes, parses with yaml.safe_load and
validates strict Pydantic schemas. It is load-once; no hot reload.

2. Strategy YAMLs are loaded separately by strategies/loader.py; invalid strategy
YAML causes fail-fast/no partial strategy set; no hot reload.

3. preflight.yaml and security.yaml are NOT part of Appconfig. They are consumed
by separate processes. They therefore must NOT be described as two of the
eight core application config files.

4. system_config.yaml contains many global controls, including trading hours,
broker/product mapping, capital/risk/sizing, queue, clock, kill/safety and
delivery controls.

5. scan_webhook_map.yaml maps Chartink scanner names to strategy names and is
startup-validated against strategy YAMLs.

6. scoring_weights.yaml contains secondary-screening weights and score thresholds.
Its old tier-multiplier block is documented as deleted/dead config; the active
position-size tier multipliers live elsewhere.

7. strategy_direction_registry.yaml mirrors strategy direction/health and does
NOT override Strategyconfig.direction.

8. config_snapshotter persists the resolved runtime Appconfig, not merely raw YAML,
as canonical JSON + SHA-256 into config_snapshots; identical date/hash is
deduplicated, while a different hash on the same date creates another row.

9. A config hash can change because raw config-file bytes changed even when values
did not; the preserved implementation specifically notes comment-only edits
can change file_hashes and therefore the resolved config hash.

10. Production is the primary historical baseline. Sandbox/Testing remains
comparison evidence only.
