B3-37. Is any premise in this sheet wrong, or is a database/state-initialization topic missing?
Answer / evidence / confidence / verify: (as below)
* Potentially Flawed Premises to Challenge:
1. ATTACH DATABASE vs. Dual Independent Connection Pools: The audit references both main.db and analytics.db. If the sheet presumes cross-database querying was done via SQLite's runtime ATTACH DATABASE command, that introduces unified lock-scope coupling (a write lock on an attached database locks the entire connection). In practice, robust architectures often maintain two separate, unattached connection handles in core/db_connect.py rather than runtime ATTACH.
2. PRAGMA Persistence Assumption: It is a mistake to assume all SQLite configurations persist in the database header. While journal_mode=WAL is persistent in the file header, critical PRAGMAs like PRAGMA foreign_keys = ON, PRAGMA busy_timeout, and PRAGMA synchronous = NORMAL are per-connection settings. If helper scripts or cron jobs open raw connections without re-executing these PRAGMAs, foreign key integrity and lock-waiting behaviors silently disappear.
3. Linear Schema Versioning: If the sheet assumes migrations are strictly monotonic integers (1 -> 2 -> 3), real-world multi-branch development often exposes git-merge collisions where two independent branches introduce conflicting schema changes under the same version target.

* Critical Missing Database / Initialization Topics:
1. WAL Checkpoint Management & Sidecar Bloat: How does the system handle checkpointing (PRAGMA wal_checkpoint(PASSIVE / TRUNCATE / RESTART))? Without active checkpoint management, long-running processes or unclosed read transactions can cause main.db-wal to grow unboundedly, slowing down recovery and restarts.
2. Online Backup API vs. Cold File Copy: How are database backups taken? Copying an active SQLite database file via filesystem commands (cp, rsync) while in WAL mode can capture torn pages or mismatched SHM/WAL frames. The audit should explicitly address whether the SQLite Online Backup API (sqlite3_backup / Python conn.backup()) is used.
