A. SHUTDOWN TRIGGERS
======================================================================
B11-A1 (SOURCE)
Writers of the shutdown event, searched across all 330 non-test .py files:
- main.py 116: module global `_shutdown_event = threading.Event()`.
- main.py 1570-1579 `_install_signal_handlers`: SIGINT and SIGTERM handler calls `_shutdown_event.set()` (1573). Installed at main.py 3958.
- main.py 1525: the eod-self-exit thread calls `shutdown_event.set()` (the same object, passed at 4141).
- main.py 1629: `_shutdown()` sets it again as its first act.
No other `.set()` of this event was found in the scope. main.py 4009-4020 records that the post-start webhook self-check USED to set it (cause of the 17-Jul outage) and since 27-Jul degrades and alarms instead; utils/startup_checks.py 805 carries the same note.
Keyboard interrupt: Ctrl+C delivers SIGINT, which goes to the same handler. No `except KeyboardInterrupt` was found in main.py's tail (4285-4293).
Other exits that are not the shutdown event: main() returns early (holiday or weekend 0, outside start window 0, lock failure 1; main.py 2085-2190); `_main_locked` returns 5, 4, 6, 3, 9 or 1 on start-up failures (2201-3899); uncaught exceptions map to exit 1 or 2 (4288-4293). These paths never reach `_shutdown()`.

B11-A2 (SOURCE)
main.py 1570-1579. SIGINT and SIGTERM; each registration is in try/except (OSError, ValueError). The handler logs the signal and calls `_shutdown_event.set()`. It does not call `_shutdown()`, exit or raise. Registration call: main.py 3958.

B11-A3 (SOURCE)
- Request to stop: a signal, or the self-exit decision.
- `_shutdown_event.set()`: only a flag. The main thread is parked in `_shutdown_event.wait()` (main.py 4249); workers that were given the event see it.
- `_shutdown()` (1599-1831): the ordered cleanup, run once by the main thread after the wait returns (4252-4277).
- Return from main(): `_main_locked` returns 0 (4278); main()'s `finally` releases the instance lock (2085-2190).
- Process exit: `sys.exit(main())` (4287). INTERP: the interpreter then waits for any non-daemon thread still alive; the HARD_KILL flatten worker is non-daemon (capital/kill_switch.py 1189-1197), so a worker that outlived the 15 s drain keeps the process alive after "Shutdown complete".

B11-A4 (SOURCE)
Only sets the event. main.py 1525 `shutdown_event.set()` then return; it never calls `_shutdown`. Caller: started at main.py 4135-4156 (daemon thread "eod-self-exit"). Consumer: the main thread's `_shutdown_event.wait()` at 4249, which then calls `_shutdown(...)` at 4252.

B11-A5 (SOURCE)
main.py 4129-4133: armed only if NOT (`--interactive` OR `--resume` OR env `TS_IGNORE_MARKET_WINDOW == "1"`). When not armed, no self-exit thread starts; the process then stops only by signal or an exception. `--status` and `--dry-run` return before the runtime loop (main() bypass list, 2085-2190); their exact exit path was not traced line by line.
