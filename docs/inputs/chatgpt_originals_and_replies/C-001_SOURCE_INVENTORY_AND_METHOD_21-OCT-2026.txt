4. PROCESS EXCEPTIONS (disclosed)
  E-1 Shared-blob fetch at the first checkout (row 3).
      What happened: the sparse list contained docs/v2_design_spec.md, a permitted path whose blob ID is identical to the blob of
      one path under docs/web_claude/ (a never-open folder). Checking out the permitted path therefore placed that blob in the
      local store, and the never-open check reported 1.
      What was and was not done: the diagnosis used the tree listing and the blob's size only; the blob was not opened, the file
      was not read, and nothing from it reached any output. The clone was deleted, cloned again, and checked out with that path
      removed; a tree-only check first confirmed that no other listed path shares a blob with a never-open path. The check then
      read 0 (rows 4 to 6). docs/v2_design_spec.md was not used as evidence.
      Lesson candidate (for the design log; not applied here): before a checkout, remove every permitted path whose blob ID
      equals a never-open path's blob ID, and treat such a path as never-open.
  E-2 Working-output exposure of an account tag.
      What happened: the masked read of signals/webhook_receiver.py, range 1-190, printed in working output only the lower-case
      form of the production account tag, which sits in a docstring at signals/webhook_receiver.py line 122.
      mask_read_lib.py's CLIENTID pattern matches upper-case identifiers only.
      What was and was not done: nothing was written to any file, and the value is not repeated anywhere. From the next read on,
      every content read went through mr.py (section 2.2), which masked such shapes in later output (for example seven in the
      WR4b tests). Both outputs were scanned for the shape (section 10).
      Lesson candidate (for the design log; not applied here): make the filter's client-ID pattern case-insensitive, and add the
      same shape to scan_ids.py.
  E-3 Option order. One call put --grep after a file name; mask_read2.py took "--grep" as a file name and stopped with an error
      after printing the requested masked range. Nothing unmasked was printed. Disclosed for completeness (no safety effect).
  Not exceptions: mask_read2.py reads docs/SYSTEM_MAP.md and DEPLOYMENT.md internally on every call to build its host-token
  mask (by design; nothing from them was printed). Two calls with a misplaced regex flag failed before printing anything.
