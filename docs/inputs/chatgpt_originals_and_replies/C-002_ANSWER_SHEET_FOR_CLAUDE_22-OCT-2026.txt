5. REQUIRED EVIDENCE LABELS
============================================================

Use these labels consistently:
- FACT (SOURCE-VERIFIED): directly supported by code/config at the pinned Production commit.
- FACT (RECORD-DERIVED): supported by a dated record/log/measurement, with scope stated.
- FACT (CONFIG): declared in a configuration file; not proof of runtime use.
- HISTORICAL (Rama-reported): user recollection or answer, attributed and dated.
- INTERPRETATION / AUDIT LEAD: plausible mechanism/inference, not measured fact.
- KNOWN DEFECT: demonstrated contradiction or faulty path, with impact and evidence.
- UNKNOWN / NOT ESTABLISHED: evidence does not establish the claim.
- OPEN QUESTION: a real choice or unresolved dependency, not a source-code lookup.

Do not call a configuration entry “active”, an alert “working”, a request “delivered”, or a control “enforced” unless the relevant caller/path or dated evidence establishes it.

For each important component, document:
SOURCE → INPUT → CALCULATION / LOGIC → VALIDATION / GUARD → OUTPUT → STORAGE / HANDOFF → NEXT CONSUMER.

For failures, show:
TRIGGER → ACTUAL BRANCH → RESPONSE/STATE → LOG/AUDIT EVIDENCE → NEXT CONSEQUENCE → UNKNOWN LIMITS.
