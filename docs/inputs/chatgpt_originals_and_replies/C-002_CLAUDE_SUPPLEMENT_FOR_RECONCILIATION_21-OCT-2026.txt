4. CHARTINK'S ALERTS GUIDE
==============================================================================
  CURRENT EXTERNAL FACT (Chartink's public "Alerts Guide", https://chartink.com/articles/alerts/alerts-guide/,
  posted 02-Feb-2018 with a page date of 17-Jun-2026; read 21-Oct-2026 through a summarising fetch, so these are
  paraphrases, not the raw page; not evidence of the legacy period):
  4.1 Frequency: every 1, 2, 3, 5, 10, 15, 20, 30, 60, 120 or 240 minutes, or at Market Open or Market Close.
  4.2 After trigger: "Continue" keeps monitoring and triggers whenever the conditions are met again; "Pause" stops
      after the first successful trigger.
  4.3 Duplicates: "Unique" gives one alert per stock for the day; "Duplicate" allows repeated notifications for the
      same stock whenever it matches again that day.
  4.4 Minimum stocks to alert: the alert fires only when at least that many stocks match.
  4.5 Delivery: email, SMS, desktop/mobile (web) and WhatsApp, one or several.
  4.6 Webhook: an HTTP POST to the URL given; a "Payload Columns" setting chooses the data fields included.
  4.7 Retries and timeouts: not described. U-07 stays UNKNOWN (the answers, Q16).

==============================================================================
  5.1 Path and name. The saved URL's path is the bare key and the scan name carries the tag: the shape the WR4b
      code expects. FACT (SOURCE-VERIFIED): _strip_account_prefix removes a leading "<primary account tag>-" or
      "<tag>_" from the normalised scan_name before WR4 compares it with the path segment; the docstring says the
      tag "comes from accounts.csv via AR12" (a never-open file, not opened).
      Evidence: signals/webhook_receiver.py lines 111 to 138.
  5.2 The token in the body. webhook_url repeating the token-bearing URL agrees with the answers' Q2.6 (the 05-Jul
      record: every stored payload to that day held the token because Chartink echoed the configured URL) and
      with Q11.2 (the stored copy's webhook_url is blanked). For this testing alert, today, the token travels in
      both the query string and the body.
  5.3 The time field. FACT (SOURCE-VERIFIED): the receiver tries "%Y-%m-%d %H:%M:%S", then "%I:%M %p", then
      "%H:%M", and its comment reads "Chartink sends "HH:MM am/pm"".
      Evidence: signals/webhook_receiver.py lines 635 to 657.
      CURRENT EXTERNAL FACT (local check, Python 3.13.16): "7:53 pm" parses under "%I:%M %p" as 19:53. Field rules
      remain C-004's (W-6).
  5.4 Cadence. One minute, Continue and Duplicate agree with R4 ("Chartink posts each scanner about once a minute",
      the answers, Q20). Agreement, not proof: R4 is production from 12-Jun to 16-Jul; the screenshot is testing
      on 21-Oct.

      for the repository. The screenshot shows that URL for one testing alert on 21-Oct only; Q4.2's lead for
      production is unchanged.

      (28-May-2024; the answers, Q2.8). So an alert cannot feed two VMs, and each system needs its own alerts
