1. SUMMARY
==============================================================================
- Where validation happens. All intake validation is in R: request-level checks in _process_request (lines 585 to 674), after the
  gates C-003 froze (authentication, scanner, EOD branch, kill switch, backpressure, entry window), and per-symbol checks in the
  loop (696 to 728) and the start of _process_signal (904 to 926). FACT (SOURCE-VERIFIED).
- Request level (the whole POST fails; no symbol is looked at): malformed JSON (400); a body that is not a JSON object (400); a
  top-level price or entry_price that will not cast to float (400; FIX-074); a missing stocks, trigger_prices or triggered_at key
  (400; presence only); a scan_name that does not match the path after lower-casing, spaces to underscores and the account-prefix
  strip (400), or that is not a string (500); a triggered_at matching none of three formats (400); stocks or trigger_prices not a
  string (400); unequal counts after splitting on commas (400). A cast that overflows (a JSON number too large for a float, or an
  Infinity literal in qty) also ends in 500, because the casts catch only ValueError and TypeError. FACT (SOURCE-VERIFIED), with
  probes for Python's behaviour. Each 400 leaves no signals row, an audit row (400, 0, 0) and a WARNING line holding the first
  1,000 bytes of the raw body; a 500 leaves no row, one CRITICAL line and (500, 0, 0) (C-003 sections 7.3 and 7.5, frozen).
- Per symbol, in order: strip; alias (the symbol upper-cased is looked up in a two-entry map from config/symbol_aliases.yaml; a
  symbol without an alias keeps its own case); the static exclusion list (five symbols, case-insensitive) ->
  REJECTED_EXCLUDED_SYMBOL; empty -> INVALID_SYMBOL; price not a float or <= 0 -> INVALID_PRICE; too old -> EXPIRED; then the
  C-005 claims, the INSERT and the queue. FACT (SOURCE-VERIFIED). The four intake rejections are response-only: no signals row,
  no queue entry and no log line, except one DEBUG line for an exclusion.
- What is not checked at intake (N-1 to N-3): symbol syntax, length or characters; case (except for aliased symbols); exchange or
  series; presence in the instrument master. Any non-empty string with a positive price passes. A non-finite price ("nan", "inf")
  also passes (probe; L-01).
- The instrument master (config/instruments.csv, absent from the tree at the pin; built by scripts/refresh_instruments.py, declared
  at 09:00 on weekdays) is loaded once at start-up and is not consulted at intake. Its consumers look symbols up by exact, case-sensitive
  key and fall back on a miss (lot size 1, tick 0.05, token 0, sector "UNKNOWN"); none of those read rejects a miss (section 7).
- The first later step that stops a symbol the broker does not return is the secondary screener's quote fetch: quote key
  "NSE:<symbol>"; no quote, or an exception, gives SKIPPED_QUOTE_UNAVAILABLE, which the screener persists (section 8; D-003).
  How the broker answered an unknown or lower-case key is not established (U-03).
- MIS eligibility is not checked at intake. It is learned from the broker's rejection ("MIS orders are currently blocked ... Place
  a CNC order instead") and applied at the screener; the pinned configuration runs that drop in shadow mode, so on the code path
  a blocked symbol is logged and continues past the pre-drop (section 8.3; FACT (CONFIG); installed value unknown). Rama's Q2 and
  Q11 describe this class of rejection.
- Whole request versus per symbol: a request-level failure returns before any symbol is handled. The batch answers 503 if any
  symbol is QUEUE_FULL or STORE_ERROR, even when other symbols in the same payload were accepted (the test at
  test_webhook_receiver.py lines 598 to 622 asserts their ACCEPTED results and stored rows), and such a batch is audited with
  counts 0 and 0 (already in C-001 D-06 and C-003 section 7.3 row 9). One unguarded path inside the INSERT's IntegrityError handler
  can still end a batch in 500, leaving that symbol's claims held (9.4; L-13, for C-005).
- Much of the edge is already frozen: the gate and check order (C-001 7.1, C-002 9, C-003 7.3), the fields read (C-001 4.3, C-002
  8.2), the alias file and its readers (C-001 7.3, A-009 3 with erratum E-2, B-002 4 and 6), the exclusion list (A-004 6, C-001 7.3),

4. PER-SYMBOL CHECKS (M-2, M-4)
==============================================================================
4.1 Order. FACT (SOURCE-VERIFIED). For each pair zipped from the two lists (R 696):
  1. alias (701-706; section 5);
  2. exclusion (708-717; section 6) -> REJECTED_EXCLUDED_SYMBOL;
  3. empty symbol (904-906) -> INVALID_SYMBOL;
  4. price (908-914): float(); ValueError or TypeError, or a value <= 0 -> INVALID_PRICE;
  5. expiry (916-926) -> EXPIRED (C-009 owns the rule);
  6. the in-flight claim (934-935) -> IN_PROCESS; the cache dedup (940-947) -> DUPLICATE; the INSERT (963-1044) -> DUPLICATE,
     STORE_ERROR, or the re-queue of an earlier QUEUE_FULL row (ACCEPTED or QUEUE_FULL); the queue (1047-1068) -> QUEUE_FULL;
     otherwise ACCEPTED (1072) (C-005 to C-007 own these).
  Steps 1 and 2 run in the loop; steps 3 to 6 in _process_signal. The resolved symbol (B2) is used from step 1 on, in the
  response, the row and the queue.

4.2 The only symbol check is emptiness (`if not symbol`, 905). FACT (SOURCE-VERIFIED). An empty element comes from an empty stocks
  string, a doubled comma or a trailing comma (probe: "".split(",") is [""]; "A,B," ends with ""). The test with " ,TCS" asserts
  INVALID_SYMBOL then ACCEPTED (test_empty_symbol_returns_invalid_symbol, 992-1005). A symbol of spaces only is stripped to empty
  first (670). Nothing at intake (signals/webhook_receiver.py) checks characters, length, case, a suffix or presence in the
  instrument master (N-1, N-2); the later stops are section 8.

4.3 Price. FACT (SOURCE-VERIFIED); probe CURRENT EXTERNAL FACT. The per-symbol price is the matching element of trigger_prices (a
  string), not the FIX-074 fields. float() accepts surrounding spaces, exponents ("1e3"), underscores ("1_000"), non-ASCII digits,
  and "nan", "inf" and "Infinity"; of these only "-inf" fails "<= 0". So a NaN or +inf trigger price passes intake and is queued
  as the float (R 1047). Stored, it is bound into the REAL column trigger_price (R 974-977): CURRENT EXTERNAL FACT (probe 2, Python's
  sqlite3 with SQLite 3.45.1) a NaN is stored as NULL and +inf as an infinity; the VMs' SQLite version is not established (L-01).
  Tests: zero (953), negative (966), non-numeric (979), and a mixed batch in which BADSTOCK at -1.0 is INVALID_PRICE between two
  accepted symbols (198-216).
