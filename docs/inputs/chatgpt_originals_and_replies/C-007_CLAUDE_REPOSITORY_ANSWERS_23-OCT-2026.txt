SUMMARY
==============================================================================
- The signals table: 14 columns, signal_id TEXT PRIMARY KEY ("sig_" plus a UUID4 hex), no DEFAULT on any column, a unique index on
  (fingerprint, fingerprint_date), three other indexes and no trigger; six tables reference it by FOREIGN KEY. Its status CHECK
  enumerates 20 values and allows five GLOB families (REJECTED*, DROPPED_*, SKIPPED_*, GATE_*, RETEST_*); the schema calls it "a
  shape/typo guard ..., NOT a closed enum". The table was rebuilt twice for that CHECK (v25 added it, v38 widened it).
- One row per accepted symbol, inserted by the receiver as QUEUED; refused symbols leave no row. Status writes go through three
  store functions (update_signal_status, release_gate_state, release_retest_state) and three direct UPDATEs (the receiver's two
  flips and eod_cleanup's expiry); a fourth direct UPDATE sets trade_id. No status write checks the row's current status except
  eod_cleanup's expiry (WHERE status = 'PROCESSING'), and the time of a status change is not stored (no updated_at column).
- 21 status-map rows (section 4). Ten enumerated values and the DROPPED_* family have no writer in the inspected scope; the
  GATE_WAITING writer has no runtime caller (B-009, frozen) and the RETEST_* writers sit behind a setting that is false in the
  repository configuration (B-006, B-009, frozen).
- Start, stop, kill and crash: no start step writes signals rows; stop and kill write REJECTED_SHUTDOWN and REJECTED_KILL_SWITCH
  (or _LATE) inside the pipeline; a crash leaves non-terminal rows that nothing repairs except eod_cleanup's next run, which
  changes PROCESSING rows triggered before its run date to EXPIRED. QUEUED, QUEUE_FULL, RESERVED, PASSED, GATE_* and RETEST_*
  waiting rows are neither repaired nor pruned in the inspected paths.
- Retention: eod_cleanup (15:50 Monday to Friday in the repository schedule) deletes rows whose status is EXPIRED, DUPLICATE or
  REJECTED*, older than signal_retention_days (90 in the repository configuration and the model's default), not linked to a trade,
  children first. db_retention leaves signals out (B-003 re-verified).
- Next consumers disagree on what is terminal: the status report, the dashboard, the system manager, eod_cleanup and the crash
  harness each use a different set (section 7). The only signal-transition table found is the crash harness's, and it does not
  match the pinned writers.
- No erratum to a frozen manual is proposed; twelve cross-topic bookmarks (section 10).
