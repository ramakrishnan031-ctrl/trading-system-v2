5. RULES R AND S (fixed in advance, applied by the driver)
==============================================================================================================================
Rule R (the trades insert):
- For each line N printed by G6 in a file of the writer list, read N:N+30 (31 lines; clamped to the file). At most 3 reads, in
  the order of the writer list and then by line; G6 lines in other files are recorded as leads, not read.
- The read shows the column list and the values only as far as the statement fits in 31 lines; whatever it does not show
  stays NOT ESTABLISHED. How the place(...) argument reaches the insert's value, if the insert is in another function, stays
  NOT ESTABLISHED (no further hop).
Rule S (the replay chain):
- From the G9 output take NAME1, the name on the nearest def line above line 46 (the signals query), and NAME2, the name on
  the nearest def line above line 75 (the first consumer line). If either is missing or not an identifier, G10 is not run.
- Count T21 in replay_signals.py first (inside W6, with ccount_c010.py); run G10 only if the count is 1 to 8, printing exactly
  that count.
- Containment of line 46 in NAME1 and of lines 75 to 95 in NAME2 is INTERPRETATION by definition order (the def lines are
  FACT).
Both rules are tested before W5 on synthetic files with the true cases and the likely false positives: an "INTO trades" in a
  comment, INTO trades_archive, lower-case "into trades", a G6 line outside the writer list, a fourth insert (cap), a nested
  def between the query and its function, a missing or non-identifier name, a T21 count of 0 or 9.
