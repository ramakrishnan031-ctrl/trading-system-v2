1. EXECUTIVE FINDINGS

The answer sheet is a useful scope checklist, but not a verified factual account. Source tracing confirms some statements and narrows or contradicts others.

Highest-priority corrections:
1. The eight files handled by core/config_loader.py are NOT all configuration sources. The inspected config/ directory has additional YAML files, CSV files, directories and strategy YAMLs. Other code reads environment variables, .env, accounts.csv and a JSON token/session file.
2. Strategy files are in config/strategies/*.yaml in the inspected production snapshot. main.py sets strategies_dir = config_dir / "strategies" (around line 3158). Do not call this repository-root strategies/*.yaml without qualification.
3. The primary loader is not the first configuration read. main() parses args, resolves config_dir, then the holiday guard reads nse_holidays_<year>.yaml before logger setup, instance lock and load_all().
4. --config PATH is a real override. If omitted, Path("config") is relative to the process current working directory.
5. The main loader uses yaml.safe_load and Pydantic v2 model_validate. Missing file -> ConfigMissingError; YAML parse error -> ConfigSchemaError; Pydantic ValidationError -> ConfigSchemaError. Empty YAML becomes {} before schema validation.
6. “All keys required/no defaults” is overbroad. extra="forbid" rejects unknown keys, but actual schemas include defaults and validators (for example, trading_hours.market_open, market_close, service_window_end and MIS timing defaults).
7. Three different mechanisms must not be conflated:
   - Raw-byte SHA-256 per file in AppConfig.file_hashes; check_config_hash compares against session.last_config_hash and logs changed files.
   - core/config_snapshotter.py hashes canonical AppConfig JSON and stores config_snapshots; failure is explicitly non-fatal in main.py.
   - core/config_validator.validate_all(strict=False) warns on unaccessed keys but raises on detected value drift.
8. The config hash comparison is not shown to be a blocking gate by itself. Follow all uses of hash_result.changed before asserting otherwise.
9. Strategy loader fails fast, but scan_strategy_errors() separately gathers all bad strategy files for an alert path. The exact invocation order and every error path still need a full main.py trace.
10. User-reported testing-VM manual changes (market times/trade limits) remain OPERATOR-REPORTED / HISTORICAL until matched to dated host evidence.
11. “No rollback mechanism existed” is not established merely by inspecting core/config_loader.py. Search deployment scripts, hooks, recovery scripts, runbooks and records.
12. “Tests validated repository templates while VM values drifted” is a plausible risk hypothesis, not yet a proven misleading-PASS incident. Do not call it a KNOWN DEFECT without a specific evidence chain.

3. VERIFIED SOURCE FACTS

A. CLI and config directory
- main.py::_parse_args (around lines 179–205) defines --mode paper|live (default paper), --config PATH (default None), --resume, --status, --dry-run, --version and --interactive.
- main.py::main resolves config_dir = Path(args.config) if args.config else Path("config").
- The checked-in deploy/systemd/trading-system.service sets WorkingDirectory, EnvironmentFile and ExecStart with --mode live and no explicit --config. This is repository unit content only, not proof of installed host state.

B. Early holiday read
- utils/holiday_guard.py::_load_holiday_set directly reads config_dir / f"nse_holidays_{year}.yaml", uses yaml.safe_load, parses date entries and caches by (config_dir, year).
- main() calls is_trading_day before logging setup, instance lock and load_all().
- main catches FileNotFoundError around the early holiday guard and proceeds. This does not mean overall startup can succeed without the holiday file: the later eight-file loader also requires nse_holidays_2026.yaml. The narrow catch does not prove malformed YAML/date handling is graceful.

C. Primary loader
- core/config_loader.py::load_all around lines 2457–2517 loops over _CONFIG_FILES; checks file existence; reads raw bytes; hashes raw bytes with SHA-256; parses with yaml.safe_load; normalises None to {}; validates with schema_cls.model_validate; returns AppConfig only after all eight files pass.
- Missing file -> ConfigMissingError.
- yaml.YAMLError -> ConfigSchemaError.
- Pydantic ValidationError -> ConfigSchemaError.
- main.py::_main_locked catches exceptions from load_all, logs CRITICAL and returns 5.
- Eight files: system_config.yaml, broker_costs.yaml, broker_limits.yaml, slippage_model.yaml, scoring_weights.yaml, scan_webhook_map.yaml, chartink_scanners.yaml, nse_holidays_2026.yaml.

D. Other checked-in config items
The inspected config/ listing also includes accounts.csv, accounts_multi_example.csv, cron_registry.yaml, expected_managers.yaml, index_universe.yaml, preflight.yaml, reference_data/, strategies/, security.yaml, strategy_direction_registry.yaml, symbol_aliases.yaml, and the eight loader-managed YAMLs. Presence in the repository does not prove every item is loaded on every startup.
- core/account_registry.py::AccountRegistry.load parses accounts.csv via csv.DictReader and validates columns/rows.
- main.py loads config_dir / "strategies".
- scripts/zerodha_login.py calls dotenv.load_dotenv() and parses a JSON token file. Thus “the main loader does not load .env” must not be generalized to the whole application.

E. Strategy loader
- main.py around line 3158 uses strategies_dir = config_dir / "strategies".
- strategies/loader.py sorts *.yaml files; no files -> ConfigSchemaError; validates each strategy; first invalid file raises; it only assigns its strategy dictionary after the loop succeeds.
- scan_strategy_errors() separately returns all invalid file/reason pairs. main.py contains an aggregated Telegram/email alert helper. Exact call/abort/alert ordering must be checked before finalising.
- The loader has an optional scan_webhook_map_path cross-validation argument; the inspected main.py call does not pass it, so do not claim that optional validation runs in that call without other evidence.

F. Hash, snapshot and usage tracking
- utils/startup_checks.py::check_config_hash compares current AppConfig.file_hashes with JSON in session.last_config_hash. If no prior usable mapping exists, it returns changed=False. Otherwise it returns/logs changed filenames. Do not call it a blocking gate by itself.
- core/config_snapshotter.py serialises canonical JSON, redacts populated string values whose keys contain password/secret/token/api_key/apikey (except keys ending _env), hashes that JSON, and writes a config_snapshots row unless same date+hash exists.
- main.py catches snapshot exceptions and logs them as non-fatal.
- AppConfig includes file_hashes; therefore a comment-only source-file edit can change the snapshot hash while effective setting values remain unchanged. Compare config_json for value changes, not hash alone.
- core/config_auditor.py defines groups A–G with PASS/INFO/WARN/BLOCK findings; some BLOCK findings can block, but not all findings are hard failures.
- main.py calls config_validator.validate_all(strict=False) near startup completion (around line 4164). Unaccessed registered keys warn in this mode; detected tracked-value drift raises ConfigValidationError.

G. Mode and environment
- Paper/live branches exist in main.py. In the inspected path, paper sets kite_client=None at an early point; live reads account registry, account-specific environment variables and token JSON before building the live client.
- The service unit has EnvironmentFile and WorkingDirectory settings. .gitignore excludes .env and other sensitive/generated categories; this is intended repository hygiene, not proof that no sensitive value was ever committed or stored elsewhere.
- No actual credential values are included here.
