1. SOURCE-VERIFIED FINDINGS

1.1 StateStore — core/state_store.py
- StateStore.__init__(db_path, schema_path=DEFAULT_SCHEMA_PATH, allow_migrate=False, market_open=False) records these inputs, creates the parent directory with mkdir(parents=True, exist_ok=True), creates thread-local connection storage, then calls _initialize_schema().
- DEFAULT_SCHEMA_PATH is the sibling core/schema.sql.
- EXPECTED_SCHEMA_VERSION is 45 in the inspected production source.
- _get_conn() uses threading.local() to cache one connection per calling thread.
- _open_connection() uses sqlite3.connect(..., isolation_level=None, check_same_thread=True, timeout=30), sets sqlite3.Row, applies connection PRAGMAs, then calls db_connect.attach_analytics().
- _CONNECTION_PRAGMAS: journal_mode=WAL; synchronous=FULL; foreign_keys=ON; temp_store=MEMORY; busy_timeout=30000.
- close() closes the calling thread's connection only; it does not close all worker-thread connections.
- checkpoint_wal() calls PRAGMA wal_checkpoint(PASSIVE); checkpoint() provides a separate TRUNCATE path with a ticker-thread guard.

Correction: do not document synchronous=NORMAL. The inspected source specifies FULL.

1.2 Migration policy — core/state_store.py and core/migrations.py
- allow_migrate defaults to False. The StateStore comments say only main.py's boot path should pass allow_migrate=True, and that migration must be refused when market_open=True.
- MigrationNotPermitted is defined for a pending migration the current process may not run.
- Therefore, “all DB openers automatically migrate” is not supported. Schema evaluation occurs during initialization, but migration authority is gated by constructor arguments and caller behaviour.
- core/migrations.py describes schema.sql as the canonical definition. Rebuild migrations create the current table definition from schema.sql, copy intersecting non-generated columns, and swap tables.
- The migration version map describes v27→v28 as relocation of candles, system_metrics and system_metrics_daily into analytics.db; later rebuilds include trades/signals. The current source target is v45.
- The migration header describes an atomic failure test for v44→v45 on a production copy. Treat this as source-commented test evidence for that scenario, not blanket proof for all migrations or historical production runs.

UNKNOWN pending full trace: exact _initialize_schema() branches, transaction/commit boundaries for each migration, behaviour for a DB ahead of code or missing metadata, and exception/alert/exit handling.

1.3 Analytics DB — core/db_connect.py and core/analytics_schema.sql
- Analytics filename is analytics.db; analytics_path_for(main_db_path) places it beside the main DB file.
- ANALYTICS_TABLES lists candles, system_metrics, system_metrics_daily.
- init_analytics_schema() opens analytics.db directly, applies WAL, FULL synchronous and 30000 ms busy_timeout, executes analytics_schema.sql, and closes the connection.
- attach_analytics() attaches the file as schema alias analytics and applies analytics.journal_mode=WAL and analytics.synchronous=FULL.
- StateStore-managed connections call attach_analytics().
- connect() opens the main DB, sets busy_timeout=30000, and optionally attaches analytics.
- connect_readonly() opens the main DB with URI mode=ro and query_only=ON; it does not attach analytics.
- analytics_schema.sql describes the three tables as relocated from schema.sql in the O6/v28 split. The migration map names relocate_analytics_tables.

Correction: do not describe analytics as only an independent connection pool. The source explicitly defines both a direct connection for schema initialization and ATTACH on working connections.

1.4 Schema — core/schema.sql
- schema_meta is a key/value table with key TEXT PRIMARY KEY and value TEXT NOT NULL; comments describe it as the source of truth for schema version/migration tracking.
- Main schema defines persistent trading entities including signals and trades.
- analytics_schema.sql separately defines the three analytics tables above.
- Build a complete table inventory from both schemas before making claims about every state category.

1.5 Fresh file / connection facts
- StateStore explicitly creates the parent directory before schema initialization.
- SQLite normally creates a missing DB file when a file path is opened successfully; permissions or later initialization failures can still prevent successful startup.
- Exact main DB paths are NOT ESTABLISHED from these modules alone: db_path is passed in by callers/configuration.
- Exact call order for init_analytics_schema() versus first attach must be traced.

3. TECHNICAL CORRECTIONS / AUDIT LEADS
A. synchronous is FULL in inspected StateStore source.
B. Analytics uses analytics.db and is attached under alias analytics on working connections; initialization also uses a direct connection.
C. Migration authority is gated by allow_migrate and market_open; trace every constructor caller.
D. StateStore's header is not enough to prove exclusive DB access because db_connect.py exposes raw SQLite helpers.
E. close() closes only the current thread's connection.
F. Both PASSIVE and TRUNCATE checkpoint methods exist; exact caller/timing must be traced.
G. EXPECTED_SCHEMA_VERSION=45 is a source-version fact, not proof of any deployed DB's version.
H. CREATE TABLE IF NOT EXISTS does not prove no destructive migration operations occur.
I. v45 atomicity comment is not blanket proof for all migrations.
J. “Not found in inspected records” is not proof an incident never happened.
