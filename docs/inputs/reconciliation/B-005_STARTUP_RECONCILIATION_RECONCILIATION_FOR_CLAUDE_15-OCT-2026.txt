============================================================
1. MOST IMPORTANT CORRECTIONS
============================================================

1. main.py explicitly calls order_reconciler.reconcile_once() before starting signal_processor/entry_gate. Later it calls order_reconciler.start(), which calls reconcile_once() again before starting the daemon poll thread. The normal traced path therefore has two reconciliation calls unless runtime state makes one a no-op.

2. reconcile_once() catches any unhandled Exception, logs it, and returns []. It does not re-raise the exception to main.py. main.py sets _startup_reconcile_done = True after the explicit call returns, regardless of whether the action list is empty.

3. A returned [] is ambiguous: no actions, a concurrent cycle skipped by the non-blocking lock, or a caught exception. It is not proof of CLEAN/PASS.

4. BrokerTimeoutError during a check is explicitly documented to log a warning, skip that check and continue. This contradicts the answer sheet's blanket assertion that broker timeout always aborts startup.

5. BrokerAuthError is counted by reconciliation cycle; after three consecutive cycles containing auth errors, the reconciler calls kill_switch.soft_kill(). This is not the same as immediate sys.exit(1) on the first auth error.

6. The RC5 header's six check names are MANUAL_CLOSE, ORPHAN_ADOPTION, HEALTHY, PARTIAL_CLOSE, POSITION_GREW and conditional ORPHAN_ORDER. Do not replace these with the answer sheet's invented generic six-check list. Additional prepasses and checks exist in the implementation.

7. The in-process position comparison builds a map keyed by p.symbol and looks up local trade["symbol"]. The answer sheet's universal claim of compound matching by symbol/exchange/product/account/order ID is not supported by this visible path. Treat this as a high-priority audit lead; do not silently generalize.

8. scripts/reconcile_positions.py identifies itself as a daily EOD symbol-by-symbol comparison at 15:45 IST, not a proven pre-market utility. Its tests prove paper mode writes a position_reconciliation row; dry_run suppresses that DB write. It is not always read-only.

9. scripts/eod_broker_reconcile.py is a distinct EOD verdict process. Its tests use VERIFIED, ISSUES, UNVERIFIED and NOT_CHECKED; missing required broker data yields UNVERIFIED. Do not merge these verdicts with in-process ReconciliationAction categories.

10. Source has a reconciliation_log persistence path for non-COSMETIC actions. This does not prove that every clean cycle, skipped check or complete broker snapshot is persisted. Persistence failures are caught and logged.

3. SOURCE FINDINGS
============================================================

A. main.py call order
- Constructs OrderReconciler with StateStore, broker adapter, FundManager, kill switch, notifier, bus, config, quote_fn=broker_adapter.get_quote and broker_orders_fn=broker_adapter.get_open_orders.
- Explicitly calls recon_actions = order_reconciler.reconcile_once() before the signal pipeline starts.
- Sets _startup_reconcile_done = True after return; logs action count if non-empty.
- Later calls order_monitor.start(), then order_reconciler.start(); start() performs another reconciliation before its poll thread.
- Asserts _startup_reconcile_done before signal_processor.start() and entry_gate.start().
Audit consequence: call ordering is established; a universally clean/complete fail-closed gate is not.

B. orders/order_reconciler.py
- Public API includes start(), stop(), reconcile_once().
- start() runs a CNC overnight-position check; optionally runs CNC GTT reconciliation (logs exception and continues); calls reconcile_once(); then starts daemon poll thread.
- Poll interval is cfg.poll_interval_sec; module header records 15 seconds as design/config value, but runtime value depends on loaded config.
- reconcile_once() uses a non-blocking lock; returns [] if another cycle is already running.
- Broad exceptions are logged and converted to [].
- BrokerTimeoutError: affected check skipped and remaining checks continue.
- BrokerAuthError: counted at cycle level; soft-kill after three consecutive cycles with auth errors.
- Non-COSMETIC actions are persisted through StateStore.insert_reconciliation_log(); persistence errors are logged.
- Header RC5 categories: MANUAL_CLOSE, ORPHAN_ADOPTION, HEALTHY, PARTIAL_CLOSE, POSITION_GREW, ORPHAN_ORDER (conditional on broker_orders_fn).
- Other code paths include GTT adoption, in-flight-entry recovery, G5b missing-SL recovery, capital/margin drift, and specialized oversell handling.
- G5b header says eligible OPEN/PARTIAL trades without active SL may trigger LTP fetch and a fresh stop-limit SL or MARKET exit. Exact guards/fallbacks need function-level review.
- Capital/margin checks are LIVE-only when adapter reports broker-equivalent margins.

C. utils/startup_checks.py
- Module contract says pure pre-flight/scenario library; no DB mutation, no sys.exit/SystemExit and no subsystem/thread construction.
- StartupScenario enum is COLD, WARM, CRASH, HALT, not the answer sheet's assumed COLD_START/WARM_START/CRASH_RECOVERY names.
- main.py calls run_all_startup_checks().
- Exact probe order and the effect of every failed check require tracing the relevant check and main.py caller; do not infer from the header.

D. Position inputs and matching
- _reconcile() calls adapter.get_positions() and StateStore.get_all_open_trades().
- Visible broker position map is keyed by p.symbol and local trades are matched by trade["symbol"].
- Visible quantity comparison uses local qty_filled and abs(broker qty). Do not claim strict signed side comparison without tracing all relevant types/branches.
- Broker positions timeout logs warning and skips checks 1–5 for that cycle.
- broker_orders_fn is supplied from broker_adapter.get_open_orders; ORPHAN_ORDER is conditional on its availability.
- The code has specialized in-flight-entry, GTT, manual-close, orphan, oversell and SL recovery paths. These require method-level descriptions, not broad assumptions.

E. scripts/reconcile_positions.py
- Header calls it a daily EOD script comparing broker open positions symbol-by-symbol to system open trades; declared schedule 15:45 IST.
- Declared statuses include OK, ORPHAN_AT_BROKER, MISSING_AT_BROKER; tests also assert QTY_MISMATCH.
- Paper mode skips broker fetch; tests show it writes position_reconciliation rows unless dry_run=True.
- Live unit tests mock broker fetch and test match/orphan/missing/mismatch outcomes.
- Existence and declared schedule do not prove a host cron entry was installed or a run occurred.

F. scripts/eod_broker_reconcile.py
- Separate EOD broker-authoritative verdict process.
- Tests establish VERIFIED, ISSUES, UNVERIFIED and NOT_CHECKED; missing required broker data -> UNVERIFIED; orphan/missing positions or required P&L discrepancy -> ISSUES.
- Margin is supplemental/reliability-gated in tests and can be NOT_CHECKED without blocking VERIFIED.
- Do not assume compound exchange/product/signed matching solely from the script description; inspect actual matching code before finalizing.
- Actual production execution/schedule is UNKNOWN without host records.

G. persistence/config/scheduler
- In-process non-COSMETIC actions are stored through insert_reconciliation_log().
- Position utility writes position_reconciliation outside dry-run; EOD verdict has its own persist path.
- Exact table names and schemas must be cross-checked with frozen B-003 and core/state_store.py.
- Reconciler receives OrderReconcilerConfig; header names poll_interval_sec and capital_drift_tolerance. Other actual fields must be extracted from the config schema.
- config/cron_registry.yaml says it is the source for generated deploy/cron/trading-system.cron; enabled:false jobs are excluded from generation. It does not prove installed host crontab or historic execution.
- Guessed keys in Gemini's sheet (ENABLE_STARTUP_RECONCILIATION, AUTO_RECOVER_STOP_LOSS, SHADOW_MODE, POSITION_DRIFT_TOLERANCE, RECONCILER_EXCHANGES, etc.) must not be documented unless exact literals are found.
