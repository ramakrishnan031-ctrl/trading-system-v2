3. HIGH-PRIORITY RECONCILIATION POINTS
R1 — “Reverse-order shutdown” is a docstring characterization, not a strict reverse of all construction order unless construction order is traced. Prefer describing the actual ordered sequence in the manual.
R2 — Drain timeout discrepancy: Claude says the `drain_flatten` docstring describes `timeout=None` for internal self-exit, while `_shutdown` passes 15 seconds. The source comments say internal self-exit cannot arrive mid-flatten because the self-exit gate waits first. Record this as doc drift, not automatically a runtime defect.
R3 — Service-window vs special sessions: source answer says `service_window_end` is not moved by special-session configuration and may precede a late special-session close. Preserve as a source-level limitation; host effects unknown.
R4 — External stop safety: external stop does not run the position gate. A still-running hard-kill flatten gets at most 15 seconds of drain before teardown continues. This is a source-level exposure boundary; do not say the system always closes positions before exit.
R5 — `_shutdown` failure semantics: per-step exceptions are generally caught and the caller returns 0. A hang, especially the unbounded signal processor executor wait, can still block subsequent cleanup. Distinguish exception from hang.
R6 — Shutdown event content: the answer says the SHUTDOWN DB event contains timestamp and event type only, not mode or reason, despite `_shutdown` accepting `mode`. This is supported by the spot-checked source.
R7 — Test coverage: two tests were read selectively; several named tests were only inventoried. Never describe uninspected tests as proving behaviour.
R8 — Source inventory scope: the 330 non-test Python search is explicitly bounded. Shell scripts, cron declarations and many docs were not searched. Do not generalize its negative findings to the repository as a whole.
R9 — Process exception: the README sparse-pattern mistake fetched one never-open blob temporarily, then was removed and the safety check returned to zero. Preserve this method disclosure in the audit trail; do not overstate that the blob was read.
